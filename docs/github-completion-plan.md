# GitHub project completion plan

User-approved scope: make downloads/onboarding clear, add accurate discovery metadata, community/reporting documentation, genuine visual demonstration, and a public repeatable native source-build/package workflow. No promises of universal compatibility, legal certification, guaranteed popularity, signing/notarization or physical-device tests without evidence.

## Tasks and ownership

- [ ] Root: README download table, quick start, screenshot gallery, real native demonstration, social preview asset and repository metadata/topics.
- [ ] Community worker: CONTRIBUTING, SUPPORT, SECURITY, conduct guidance, issue/PR templates, changelog and bounded roadmap/manual acceptance matrix.
- [ ] Automation worker: public manually dispatched matched-source validation on all three native targets, no hardcoded private run dependencies, bounded artifacts, doc-only checks and efficient source CI filters/cache.
- [ ] Root/reviewer: validate links/templates/source binding/privacy, execute native workflow and check its evidence, publish source/docs changes and verify rendered GitHub pages/settings.

## Global constraints

App remains English, Rust/egui, version2.3.1; existing released assets and source tag are immutable. Existing video geometry/cadence/timeline and strict target-byte invariants remain. Do not change frozen codec recipe/lock/BUILD.md or source ZIP binding. App code has MIT terms; dependencies retain theirs. Security reports use GitHub private reporting, never an invented email or service-level promise. No external announcement/messages, artificial stars or paid enrollment.

## Acceptance

Direct download links resolve to the existing verified assets. Public docs distinguish source CI from matched-runtime acceptance and from NOT_RUN manual/physical testing. All new automation runs with read-only repository permissions and no paid runner labels. All three native jobs must pass, including actual extracted package rendering. Generated media uses only project assets and generated sample input; no private user media/paths. Social preview must be visibly configured, not merely saved locally. No signing or manual-physical acceptance is claimed without real evidence.
